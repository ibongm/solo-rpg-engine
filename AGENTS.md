# AGENTS.md — Operational Instructions & Engineering Guidelines

This document governs all AI agents, automated assistants, and human engineers contributing to the **Solo RPG Engine**. Adhere strictly to these directives across all design, implementation, and maintenance tasks.

---

## 1. Non-Negotiable Coding Standards

* **Full Copy-Pasteable Files Only:** NEVER output partial code, stubs, or placeholders like `// ... rest of code here`, `// TODO: implement`, or truncated functions. Every file created or updated must be 100% complete, fully typed/documented where applicable, and production-ready.
* **Strict Separation of Concerns:**
  * **The Frontend (`src/engine/*`) is the Deterministic Rules Lawyer:**
    * All dice calculations (`d20 + statMod + proficiency + weatherMod + itemMod`), HP/currency clamping, clock progression, timed quest expiration, and minigames MUST run deterministically in pure JavaScript.
    * Never permit the LLM to roll dice or calculate numerical game mechanics.
  * **The Backend (`api/*`) is the Storyteller & State Proposer:**
    * All interactions with Google Cloud Vertex AI go through Vercel Serverless Functions using `@google/genai` (or `@google-cloud/vertexai`), strictly validating payloads against schemas in `api/_lib/schemas.js`.
* **Prohibited Mechanics (Strictly Forbidden):**
  * **NO secret/hidden DM rolls:** All DCs, modifiers, advantages/disadvantages, and roll triggers must be transparent and visible to the player.
  * **NO timeline rewinds / multiverse branching:** Permadeath upon 3 failed Death Saves is final. The only exception is the single "Edit Last Turn" anti-glitch correction on the most recent narrative log entry.
  * **NO manual "Add Companion" buttons:** Companions can only transition to `isRecruited: true` through organic narrative state updates generated by the engine.
  * **NO ambient audio / soundboard modules:** The application is purely visual, textual, and tactical.

---

## 2. Mandatory Change Tracking

* **Every change MUST be documented in `CHANGELOG.md`:**
  * Whenever you add a feature, refactor code, reorganize directories, adjust configurations, or fix bugs, you must append an entry to `CHANGELOG.md` under the appropriate section:
    * `Added`: for new features or capabilities.
    * `Changed`: for changes in existing functionality or structural updates.
    * `Deprecated`: for soon-to-be removed features.
    * `Removed`: for now removed features.
    * `Fixed`: for any bug fixes.
    * `Security`: in case of vulnerabilities.
* Follow the [Keep a Changelog](https://keepachangelog.com/) standard and Semantic Versioning principles.

## 3. Environment Variables Specification

Ensure all local environments (`.env.local`) and Vercel production settings define the following parameters:

### Frontend (Vite)
* `VITE_FIREBASE_API_KEY`: Firebase web API key.
* `VITE_FIREBASE_AUTH_DOMAIN`: Firebase authentication domain (e.g., `your-project.firebaseapp.com` or `localhost`).
* `VITE_FIREBASE_PROJECT_ID`: Firebase project identifier.
* `VITE_FIREBASE_STORAGE_BUCKET`: Storage bucket identifier.
* `VITE_FIREBASE_MESSAGING_SENDER_ID`: Cloud messaging sender ID.
* `VITE_FIREBASE_APP_ID`: Firebase web app application ID.
* `VITE_USE_EMULATORS`: Set to `true` when running against local Firebase emulators.

### Backend (Vercel Serverless / Vertex AI)
* `GCP_PROJECT_ID`: Google Cloud project ID.
* `GCP_LOCATION`: Google Cloud region (e.g., `us-central1` or `europe-west1`).
* `GCP_SERVICE_ACCOUNT_KEY`: Base64-encoded or raw JSON service account credentials possessing `roles/aiplatform.user` and `roles/storage.objectAdmin`.
* `VERTEX_MOCK`: Set to `1` when testing locally without live Vertex AI cloud credentials.

## 4. UI & UX Polish Requirements

* **Design System & Multi-Genre Theming:**
  * Use **Tailwind CSS** paired with CSS custom variables defined in `src/styles/themes.css`.
  * Support instant dynamic switching between:
    * `fantasy`: Warm parchment, crimson accents, serif typography.
    * `frontier_noir`: Stark cream/charcoal, high-contrast ink borders, slab-serif typography.
    * `scifi`: Deep slate/obsidian, cyan/emerald neon accents, monospace typography.
  * Switching themes must never trigger a full page reload or loss of ephemeral state.
* **Layout Geometry:**
  * Maintain the desktop split: **60% Left/Center Game Stage** / **40% Right Command Sidebar**.
  * Keep keyboard navigation active: hotkeys `1`–`6` switch sidebar tabs whenever focus is outside text input fields.
* **Offline Resilience:**
  * Maintain the **Local Retry Queue**: Uncommitted player actions must be written to `localStorage` before initiating calls to `/api/dm-turn`, and must be pruned only once Firestore confirms the state mutation commit.

---

## 5. Verification & Testing Standards

* Before committing or finalizing any task:
  * Run the unit test suite: `npm run test` (Vitest). All tests in `src/engine/*.test.js` and `api/*.test.js` must pass.
  * Verify the production bundle: `npm run build` (Vite).
  * Ensure no lint or syntax issues are introduced.
